## 壁打ち(反証 2件)

### 1. verdict=**revise** recall:neutral / precision:improves / data支持:True / 既出:False
- 反論: Is the bare-no-tests false positive a broad systemic hole or a narrow model-specific quirk being over-generalized into a rubric-wide rule? Of the 11 total false positives in this run, 5 are bare no-tests-added Medium-severity filings, and 4 of those 5 belong to sonnet specifically, occurring across four different, unrelated fixtures (a validator diff, a rate-limiter diff, a thumbnail-cache diff, an order-processor refactor). That is the single largest coherent false-positive category in the entire run, and it recurs on fixtures with completely different subject matter, so it is not an artifact of one fixture's wording. It is also directly traceable to a contradiction already present in the file: severity-rubric.md line 10 lists "missing test for new behavior" as a textbook Medium example, and review-checklist.md's Tests section instructs the reviewer to check exactly that. The model is following the rubric as written. Does fixing this risk suppressing genuinely valid test-related findings? The one borderline case, prec-refactor/sonnet Finding 5 about a test's inability to catch bugs 2 and 3, actually supports the proposal: it was scored a false positive precisely because it was filed as a standalone coverage-gap Medium instead of reporting bugs 2 and 3 themselves at full severity, which is exactly the redirection the proposal prescribes.
- 応答: The gap is reproducible across four fixtures and one dominant model, and it is structurally caused by the current file's own wording rather than a one-off phrasing issue, so it is worth fixing at the source instead of hoping future prompts word around it. It does not touch recall: no ground-truth planted defect across the six fixtures is a bare no-tests-added observation, so removing that phrase from the Medium row and reframing the Tests checklist cannot cause the reviewer to skip a real planted bug. The fixture with an actual test-adjacent planted bug, prec-tests, has its bug as a live fail-closed rate-limiter defect, not a test-coverage defect, and stays fully coverable via the Correctness and Resource-exhaustion sections untouched by this edit. The one risk worth guarding against is over-trimming the Tests section so far that it also suppresses the legitimate "tests assert real outcomes, not tautologies or mocked-away logic" bullet, which flags an actual defect in the test code itself, not an absence of tests, and should stay independently reportable.

### 2. verdict=**revise** recall:neutral / precision:improves / data支持:True / 既出:False
- 反論: Two attacks. (1) Recall collision with prec-tests bug-1: the proposal's clause "a defect claim depending on code not present in the diff → raise at most as a Question at the severity it would carry if true" would reinforce the exact over-hedging the evidence flags as a miscalibration — sonnet correctly nailed the Go zero-value fail-closed rate-limiter bug (right mechanism, right failure scenario) but downgraded it to a Question because it couldn't see the config-loading call site; ground truth wants that at High because zero-value-on-new-field is a standard risk needing no external read. A blunt "unread-code → Question" rule teaches reviewers to hedge precisely the confident-High findings ground truth demands. (2) Partial redundancy with Section 2 ("read surrounding code") and the existing auth paragraph, so it may add words without moving the needle.
- 応答: The redundancy attack fails: Section 2 is a general exhortation and the auth paragraph is explicitly auth/IDOR-scoped; neither names the two reproduced failure modes (asserting a validator's internals about an omitted/undefined field; flagging a partial-diff import/type/file as a compile break). The gap is real and reproducible — 2 fixtures, 3 model instances, one root cause — and orthogonal to R5's regex/ReDoS additions. The recall attack is valid but narrow and fixable: if the primary instruction is to Read/Grep the referenced code (reading confirms→assert, or refutes→drop, never suppressing a confirmable bug) and the unreadable-fallback carves out established language/runtime semantics, recall stays neutral while precision rises on both benign-lookalike fixtures. That is a revise, not a reject.

### 2. file=`SKILL.md` recall:neutral / precision:improves

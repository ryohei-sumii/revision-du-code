### 1. [medium] file=`review-checklist.md`
- **狙う穴**: ReDoS class regex-correctness misses: redos-url (redirect-validation bypass, 2/3 caught) and redos-sanitize (soft-hyphen-noop sanitizer, 4/6 caught), plus redos-email overlong-email-accepted (5/6).

Consistent across fixtures, not single-fixture noise.
- **提案**: Add a 'Regex correctness' bullet group under Security (or Correctness) covering what a pattern actually matches/rejects, independent of performance: (1) Anchoring — a validation/allowlist regex without full anchors (^...$ or \A...\z) matches a substring, so `https://evil.com/?u=trusted.com` or an embedded token passes a host/URL/redirect check; confirm URL and allowlist validators are fully anchored. Frame each as 'name the exact input that wrongly passes/fails', matching the diff-scoped, concrete-failure-scenario style already in the skill.
- **予想効果**: Raises ReDoS-class recall by giving reviewers an explicit lens for the regex-correctness bugs that are actually being missed (permissive validators, no-op sanitizers, unanchored redirect checks), which the current skill never names. Low FP risk since each check demands a concrete passing/failing input.

### 2. [medium] file=`review-checklist.md`
- **狙う穴**: ReDoS-class false positives: benign nested-quantifier EMAIL_REGEX `([\w.%+\-]+)+` flagged as catastrophic backtracking across opus, sonnet, and haiku (3 of 10 total FPs), including Critical/High mislabels.
- **証拠の強さ**: 3 of 10 false positives are the identical EMAIL_REGEX nested-quantifier pattern, reproduced across all 3 models (opus/sonnet/haiku), with 2 accompanying severity miscalibrations (Critical/High). Empirically verified benign (linear up to 50k chars in Ruby 3.3.6). Cross-model, cross-sample — a systematic gap, not noise.
- **提案**: Add a precise catastrophic-backtracking (ReDoS) bullet with a substantiation gate. State the true shapes: a quantifier over a group that itself contains a quantifier or overlapping alternation able to match the same substring more than one way (ambiguous partition), AND a required trailing/anchored token the input can fail (e.g. `(a+)+$`, `(a*)*`, `(a|aa)+`, `(\w+\s?)*$`). Then require, before flagging: exhibit a concrete input that forces super-linear steps, AND account for the engine — many modern engines mitigate the classic `(a+)+` shape (RE2, Rust regex, recent Ruby/Onigmo, .NET with backtracking limits). If you cannot both construct the pathological input and identify a non-mitigating backtracking engine, it is NOT a confirmed ReDoS — raise it at most as a Question, never Critical/High. Explicitly note that a nested quantifier alone (e.g. `([\w.%+\-]+)+`) is not sufficient evidence.
- **予想効果**: Cuts the most reproducible false-positive in the suite (benign nested-quantifier flagged as catastrophic across all three models) and fixes the associated Critical/High over-severity, while the shape list still preserves recall for genuine backtracking. Net precision gain with no expected recall loss, since the actual ReDoS-class misses are correctness bugs, not backtracking.

## 壁打ち(反証 2件)

### 1. verdict=**revise** recall:neutral / precision:improves / data支持:True / 既出:False
- 反論: Two weaknesses. (1) The evidence is single-fixture, not multi-fixture: all 3 FPs are the same EMAIL_REGEX pattern in the redos-email fixture, reproduced across models — cross-model, not cross-fixture. The proposal's "cross-sample, systematic" framing inflates this. It's still the most reproducible FP in the suite (3/10 + 2 severity miscalibrations), so worth fixing, but the multi-fixture justification is thin. (2) Recall hazard in the engine-mitigation clause: ReDoS is already the lowest-recall class (0.73), and the clause 'recent Ruby/Onigmo mitigates this shape' is the shakier sonnet rationalization, not the correct structural one. The EMAIL_REGEX is benign because [\w.%+\-]+ has no internal ambiguity — NOT because the engine mitigates. Teaching 'the engine probably mitigates' as a reason to downgrade risks the reverse FP: waving off a genuine (a+)+$ ReDoS on a non-mitigating engine, harming recall on the exact class that's already weakest.
- 応答: The fix is still net-positive because the PRIMARY gate — structural ambiguity (a quantified group that can partition the same substring more than one way) plus a required constructed pathological input — is correct, is the real discriminator, and by itself kills all 3 FPs and the Critical/High inflation without suppressing genuine backtracking (a real ReDoS can always exhibit the pathological input, so a competent reviewer still flags (a+)+$ on JS/Python/PCRE/Java at High). The genuine ReDoS-class misses are validation/correctness bugs, not backtracking, so this gate does not touch them — recall on the class as measured is unaffected. So keep the substance, demote the engine clause.

### 2. verdict=**revise** recall:improves / precision:neutral / data支持:True / 既出:False
- 反論: Checked both reference files: there is no existing regex-specific guidance anywhere (grep for regex/saniti/anchor/escape in review-checklist.md and severity-rubric.md turns up nothing but an unrelated 'unsanitized' substring match). This keeps the checklist's shape stable while still making the previously-implicit validation bullet concrete enough to catch what models are currently missing.

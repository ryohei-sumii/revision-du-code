# コスト改善ログ / Cost Improvement Log

品質トラック（`../improvement-log.md`）が recall/precision を測定駆動で改善したのに続き、
このログは **コスト（トークン消費・実行時間・モデル配分）** を同じループ
（測定 → 敵対的検証 → 適用）で改善する記録です。

> 生きたログです。ラウンドごとに追記します。生データは同フォルダの `round-N-*.md` /
> `baseline-token-usage.md` に、全体の学びは本ファイルに集約します。

---

## 0. なぜコストを別トラックで測るのか / Why cost is its own track

品質は「見逃さない（recall）／誤検出しない（precision）」の2軸。コストは第3の軸で、
**品質とトレードオフの関係**にある。

- **recall↔cost の振り子。** 本スキル最大のトークン消費源は `SKILL.md §2`「周辺コードを
  読んでから判断せよ」——これは recall を上げる指示そのもの。読み込みを削れば安くなるが
  見落としが増える。品質側の recall↔precision の振り子に対応する、コスト版の振り子。
- **だから独立トラック。** 片軸（コスト）を動かしたときの逆軸（品質）への反動を定量で追う
  には、品質と混ぜず別々に測る必要がある（品質側 Round 2 の「振り子の反動は測るまで見えない」
  の再適用）。

## 1. コストについての学び / What this teaches about cost

（ラウンドを重ねるごとに追記。現時点はベースライン Round 0 から得たもの。）

1. **固定費は progressive disclosure で既に最小化されている。**
   スキル指示は総 ~5〜6k tok だが、1回のレビューで常時載るのは `description` ~85 tok のみ。
   references はレビューが必要とした時だけ載り、プロンプトキャッシュも効く。**段階的開示は
   品質対策（中間忘却）であると同時に、そのままコスト対策**。→ 固定費側の削り代は乏しい。

2. **可変費（周辺コード読み込み）が総コストを支配する。**
   1回のトークンの大半は diff 本体 + `SKILL.md §2` の周辺コード Read。しかもその読み込み指示は
   品質（recall）を担う中核。→ **削減の主戦場は「出力短縮」ではなく「入力（何を読むか）の制御」**、
   かつ削減は必ず recall を巻き込む。

3. **測れないものは最適化できない。**
   8ラウンドの品質改善は、トークンを一度も第一級メトリクスにしなかった（`round-*-result.md` の
   トークン欄は `?` のまま、ハード数値は R1「約60万」のみ）。品質側「プロンプトは走らせて観察
   するしか検証できない（学び5）」の対:**コストも実測が唯一の真実**。コスト・ラウンドはまず
   計測の実装から始める。

4. **投資対効果は「よく走る側」に効く施策ほど高い。**
   単発レビュー（実測 ~40k tok / Opus 4.8 で ~$0.38）の削減は使うたびに効く。改善ループ自体
   （1ラウンド ~600k+ tok / ~$8）の削減は、収束したら止める（Round 8 の収束宣言）が最大の一手だった。
   → 施策の優先度は「実行頻度 × 1回あたり削減量」で決める。

5. **可変費はコードベースの読込スコープに比例し、diff サイズには（小規模では）比例しない。**（Round 1 実測）
   レビュアーは **diff が1ファイル12行でもほぼ全コードベースを読む**。small で周辺読込は diff 本体の **5.4倍**。
   → Round 0 の「コストは diff で強くスケール」は**反証**。削減の主対象は「差分の大きさ」でなく「読むスコープ」。
   これは recall を担う `SKILL.md §2`「周辺を読め」そのもの＝**recall↔cost トレードオフの実体**。

6. **エージェント的コストは "content×ターン数" で膨らむ（再送乗数）。**（Round 1 実測）
   コンテキストの単一コピーは ~8.6k tok だが metered input は ~31.5k（**乗数 ≈ 3.7×**）。約15ツールターンで
   毎ターン再送されるため（キャッシュで一部緩和）。静的バイト計算では見えない。→ キャッシュ安定化と
   ツール往復削減が効く。**出力の約8割も推論＋ツール生成**で、最終レビュー文は2割弱。

7. **見積もりは測るまで当たらない（コスト版）。**（Round 1 実測）
   固定費 ~5k と input 支配は当たったが、「diff でスケール」と「出力 0.3〜3k」は外れた。
   品質側の学び「プロンプトは走らせて観察が唯一の検証」の**コスト版**: トークンも実測が唯一の真実。

8. **recall↔cost の振り子は非対称に振れる——安く削れる領域が実在する。**（Round 2 実測）
   読込を**−23%**削った予算制でも、本物バグの recall 損失は実質ゼロ（全体 −0.03＝ノイズ、
   **失われたバグ0**）、precision はむしろ改善（0.97→1.0・誤検出 1→0）。「読む＝コスト＝recall」の
   一次近似は粗い。削減の本丸は「読む**量**」でなく「読む**対象の選別**」——判断が変わるハンクだけ読む。

9. **削っていい読込と絶対削れない読込は"バグクラス"で分かれる。**（Round 2 実測）
   自己完結ハンク（整形・局所リファクタ）の周辺読込は捨てて良い。**契約変更**と**並行/共有状態**の
   周辺読込は捨てると本物を逃す（Go 無制限 goroutine ファンアウトが予算制で 2/2→1/2 に劣化）。
   均一な「全部読め／予算内で読め」より、**トリガー起動の条件付き全読込（hybrid）**が最適。
   → `SKILL.md §2` を hybrid に改訂（既定は予算制、契約/guard・並行の2トリガーで読込必須化）。

10. **平均は本物の後退を隠す——敵対ゲートは"却下し損ね"を防ぐために効く。**（Round 2 実測）
    クラス recall は 0.81 で不変に見えたが、それは並行バグの劣化を無関係な冪等性バグの改善が相殺した
    見かけ。判定側はこの**クラス内相殺**を見抜いて純予算制を却下し hybrid にした。コスト施策も品質と
    同じ敵対ループ（測定→敵対検証→適用）で検証でき、集計平均だけ見ると危険。

### Round 1 — 実測: 1回あたりトークンの計測（完了・スキル変更なし）

- **狙い:** Round 0 の見積もりを**実測で置換**。現実的な小コードベース＋小/中/大 diff の3フィクスチャを

### Round 2 — recall↔cost の振り子（完了・**スキル変更あり: hybrid 採用**）

- **状態:** ✅ 完了。生データは `round-2-pendulum.md`。
- **狙い:** Round 1 が特定した最大レバー＝`§2` 周辺読込を実際に削ったら何が起きるかを A/B で実測。
- **手法:** 同一モデル（Sonnet）で §2 を「フル読込(A)」vs「予算制=差分ファイル＋1ホップ呼び出し側のみ(B)」に
  差し替え。4フィクスチャ×2変種×2 run。仕込みバグを `in-diff` / `requires-surrounding-read` にタグ付けし、
  **コスト（開いたファイル数）と recall/precision を同時測定**。敵対ゲート(Opus)＋判定(Opus・提案のみ)。
- **実測:** 読込 **−23%**（6.13→4.75 file/回）に対し recall **0.90→0.87（−0.03＝ノイズ、失われたバグ0）**、
  precision **0.97→1.0**（誤検出 1→0）。本命の `requires-surrounding-read` クラスは **0.81 で不変**。
  唯一の方向性後退は Go 無制限 goroutine ファンアウト（並行・2/2→1/2）。26体・881k tok・約28分。
- **判定:** ゲート = budget-acceptable、判定 = **adopt-hybrid**。純予算制は並行クラスを運任せにするため、
  **既定は予算制＋「契約/guard 変更」「並行/共有状態」の2トリガーで読込必須化**する hybrid を `§2` に適用。
- **得た学び:** 上記「1.」に 8〜10 を追加。

## 3. 用語 / Glossary

- **固定費 / fixed cost** … 差分の中身によらず載るトークン（スキル指示など）。キャッシュ可。
- **可変費 / variable cost** … 差分サイズ・周辺読み込みに比例するトークン。主たる課金対象。
- **recall↔cost トレードオフ** … 読み込み（＝コスト）を削ると見落とし（＝recall 低下）が増える関係。
  品質側 recall↔precision の振り子のコスト版。
- **メタコスト / meta-cost** … スキルを「使う」コストではなく「改善する」コスト（改善ワークフロー）。
- **プロンプトキャッシュ / prompt caching** … 直前と共通の入力接頭辞を再利用し、固定費を初回以降
  ほぼ無料化する仕組み。固定オーバーヘッドが小さく効く前提。

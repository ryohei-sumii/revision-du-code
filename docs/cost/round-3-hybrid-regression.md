# Round 3 — hybrid の回帰検証 / Did the Hybrid Actually Deliver? (A/B/H, 敵対ゲート付き)

**日付:** 2026-07-07 ／ **状態:** ✅ 完了・**仮説は反証／§2 を小幅修正** ／
**手法:** 3変種（フル読込・純予算制・hybrid）を並行/契約重視のフィクスチャで走らせ、
**バグクラス別 recall**（第一級指標）とコストを実測。別モデルの敵対ゲート付き。

Round 2 は「hybrid は並行クラスの recall を守りつつ安くなる」と結論した。だが Round 2 の根拠は
**単一 run のフリップ1件**だった。本ラウンドは並行バグを6個に増やし、hybrid が本当に効くかを検証。

---

## 1. 実験デザイン / What we tested

Round 2 の A/B に **H（適用済みの hybrid §2）** を加えた3変種（レビュアーは全部 Sonnet 5、§2 だけ差し替え）:

| 変種 | §2 | 検証する主張 |
|---|---|---|
| **A** | フル読込 | recall の上限（周辺を全部読めば最も捕れる、という Round 2 の前提）|
| **B** | 純予算制 | 安いが並行クラスを危険にさらす（Round 2 の懸念）|
| **H** | **hybrid（適用済み）** | **並行/契約クラスの recall を A 水準に回復しつつ、コストは B 並みに保つ** |

- **フィクスチャ（並行・契約に重み付け）:** Go worker-pool（並行3）・JS async batch（並行3）・
  TS 契約/guard（契約3）・Python mixed（契約1＋自己完結の大リファクタ）。各 `klass_group`
  （concurrency/contract-guard/other）と `detectability` でタグ付け、**自己完結ハンク**も明示
  （hybrid が無駄読みしないかの検証用）。
- **各変種 各フィクスチャ 2 run。** レビュアーは実ファイルを Read/Grep、指摘＋開いたファイル一覧
  （＝コスト）を報告。判定(Opus)は location＋欠陥主張で厳格照合。
- **本命指標:** Round 2 の教訓「集計平均はクラス別後退を隠す」に従い、**バグクラス別 recall を第一級に**。
- 規模: 34エージェント・エラー0・総 **1,179,654 tok**・317ツール・約32.3分。

## 2. 実測結果 — 仮説は反証された / Results — hypothesis refuted

### ヘッドライン（driver は太字）

| 指標 | A フル | B 純予算 | H hybrid |
|---|--:|--:|--:|
| Recall 全体（14チェック） | 0.82 | **0.89** | 0.86 |
| **└ concurrency（6・本命）** | **0.58** | **0.75** | **0.67** |
| └ contract-guard（4） | 1.00 | 1.00 | 1.00 |
| └ other（4） | 1.00 | 1.00 | 1.00 |
| Precision | 0.79 | **0.90** | 0.87 |
| 誤検出（FP） | **7** | 3 | 4 |
| **平均読込ファイル数/回（コスト）** | 6.25 | 5.88 | **4.75** |

**予想と真逆の順序になった:**
- **フル読込 A が並行 recall で最下位（0.58）**、しかも**誤検出が最多（7）**。「読むほど捕れる」は成り立たず、
  むしろ**読むほど注意が薄まり(lost-in-the-middle)・誤検出の面積が増えた**。
- **純予算制 B が recall・precision の両方でトップ**（0.89 / 0.90）。焦点を絞ったほうが本物を捕り、誤報も少ない。
- **hybrid H は最安（4.75 file）だが、並行 recall は B に届かず（0.67 < 0.75）**。「A 水準への回復」は起きなかった。
  contract-guard は3変種とも 1.0 で**飽和**——トリガーが回復を示す余地がそもそも無い（回復の主張は空虚）。

### 敵対ゲートの判定: **`hybrid-no-better-than-budget`**

> concurrency（planted 6）: A=0.58, B=0.75, H=0.67。**H は純予算 B より低い**——hybrid は"余地のある唯一の
> クラス"で B に**劣る**。per-bug が理由を示す: JS `bug2-fireforget-missing-await` は A0/B1/H0——**予算制が
> 捕るのに hybrid のトリガーは発火せず/助けにならず取り逃す**。contract-guard は A=B=H=1.0 の飽和タイで
> トリガーの出番ゼロ。**どちらの保護クラスでも H は B を上回らない**。コスト面（攻撃2）は不発——H は最安。
> だが安さは、両保護クラスで失敗した recall 主張を救えない。

## 3. 判定と適用 — `adjust-hybrid`（§2 小幅修正）/ Decision

判定(Opus, 提案のみ)は **`revert-to-full` を却下**（フル読込 A は並行 recall 最下位＋最高コストで B に**完全劣位**、
戻せば保護クラスが悪化）、**`keep-hybrid` も却下**（ゲートに対して不誠実）、**`adjust-hybrid`** を採択。
本ラウンドが暴いた2つの具体的欠陥を修正:

1. **override 読込が予算読込を"置換"していた（"追加"でなく）。** avgFilesH=4.75 は全変種で最少（B の 5.88 未満）。
   「自己完結はスキップ」が効きすぎ、トリガー読込が予算枠を食い、**バグのあるファイルを読み損ねた**。
   → §2 に「override 読込は予算に**上乗せ**（置換でない）」を明記。
2. **fire-and-forget は呼び出し**先**を読まねば見えない。** 失った bug2（A0/B1/H0）は、未 await の呼び出しが
   promise/future を返すことを**callee 定義を読んで初めて**判別できる。トリガーは enclosing/spawn 側しか
   指していなかった。→ §2 に「結果を捨てている呼び出しは callee 定義を読んでから同期と結論せよ」を追加。

**適用（本コミット）:** `SKILL.md §2` の「Concurrency / shared state」箇条に上記2文を追記。
※ 判定案にあった「並行レビューは非並行レビューより読込ファイル数を減らしてはならない」という**ファイル数を直接
縛る文言は採用しなかった**——それは目的（recall）でなく代理指標（file count）を最適化させ、水増し読みを招く。
意図（"スキップ"に override を諦めさせない）だけを言葉にした。

## 4. この計測が確立した学び / What this round teaches

（→ `cost-log.md §1` に 11〜13 として集約）

1. **「読むほど良い」は偽——レビューにも lost-in-the-middle がある。** フル読込 A は並行 recall 最下位(0.58)＋
   誤検出最多(7)。周辺コンテキストを増やすと、本物のバグに割く注意が薄まり、かつ**誤報の材料が増える**。
   Round 2 の暗黙前提「フル読込が recall の上限」は**反証**。可変費（読込）は recall と単調でない——
   **多く読むことはコスト増と recall 減/precision 減を同時に招きうる**。これはコスト削減にとって朗報:
   焦点化は安くて質も高い。
2. **純予算制がこの題材では recall・precision とも最良。** 焦点を絞った B が両質軸でトップ、かつほぼ最安。
   「予算制＝品質を削る」という直観は、少なくとも小コードベースでは支持されない。**削減の余地は
   思っていたより大きい**（Round 2 学び8の強化）。
3. **手の込んだ機構（hybrid のトリガー群）は、単純案（純予算制）に勝つとは限らない——測って初めて分かる。**
   Round 2 で単一フリップから作った hybrid は、6バグで測ると B を上回らなかった。**自作の改善を、次の
   ラウンドで敵対的に回帰検証しないと、ノイズを機能と誤認する**。品質側8ラウンドと同じ規律をコストにも。
4. **敵対ゲートが自作機構を却下する価値。** ゲートは「トリガーは B に対し recall 利得ゼロ」と正直に断じ、
   判定は revert でも keep でもなく、**具体的欠陥2点の修正**に落とした。モデル同士の壁打ちが、
   希望的観測（hybrid は効いているはず）を防いだ。

## 5. 未解決 / Open questions（次ラウンドへ）

- **hybrid vs 純予算制の決着がついていない。** 本ラウンドで B ≥ H。修正後の H が B に**追いつく/超える**かは
  未検証。次は「修正 H」対「純予算 B」を並行重視・**より大きな標本**（並行バグ12+、run 3+）で対決させ、
  hybrid の複雑さが純予算制に対して**実際に recall を買っているか**を決める。買っていなければ、
  **hybrid を捨てて純予算制に単純化**する選択肢が濃厚（オッカムの剃刀＋本ラウンドの B 優位）。
- **飽和クラスは実験にならない。** contract-guard は3変種とも 1.0。差を測るには**より難しい契約/guard バグ**
  （guard が2層・呼び出し側が複数モジュール等）が要る。
